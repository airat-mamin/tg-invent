# Шаблоны разбора шильдиков

Правила распознавания вынесены из кода в конфигурацию, потому что у каждого
производителя свой формат идентификаторов. Добавление нового вендора не требует
изменений в коде — достаточно положить сюда файл.

```
templates/
├── common.yaml        общие правила: бренды, метки, форма модели, шум
└── vendors/
    └── dell.yaml      правила конкретного производителя
```

Файлы читаются при старте бота. Ошибка в шаблоне останавливает запуск с
сообщением, в каком файле и в каком поле проблема: тихо работать по
полуисправной конфигурации хуже, чем не стартовать.

Каталог задаётся переменной `TEMPLATES_DIR`, по умолчанию — `templates` в корне
проекта.

## common.yaml

| Поле | Назначение |
| --- | --- |
| `brands` | Производители, которые бот узнаёт в тексте наклейки. Сравнение нечёткое: допускается одна ошибка OCR в слове от четырёх символов |
| `labels.service_tag`, `labels.serial`, `labels.model` | Регулярные выражения меток, после которых идёт значение. Группа 1 — само значение |
| `model.token_pattern` | Форма обозначения модели для случая, когда метки на наклейке нет или она на незнакомом языке |
| `model.stopwords` | Слова, которые никогда не являются моделью |
| `noise.labels` | Метки, после которых идёт не идентификатор оборудования: `P/N`, `FCC ID` и подобные |
| `noise.values` | Значения-заглушки, приводимые к пустому полю |
| `validation.*` | Формат, которому обязано соответствовать значение перед сохранением |

## vendors/<название>.yaml

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `brand` | да | Название производителя в верхнем регистре |
| `aliases` | нет | Написания бренда на наклейках |
| `serial.pattern` | нет | Формат серийного номера. По нему бот узнаёт производителя даже когда на фото читается только штрихкод |
| `serial.length` | нет | Допустимый диапазон длины `[минимум, максимум]` |
| `serial.hyphens` | нет | `separator` — дефисы только разделяют группы и в машинном виде убираются; `significant` — дефис является частью номера |
| `serial.groups` | нет | Разбивка на группы для показа «как на наклейке», ключ — длина машинного вида |
| `serial.fixes` | нет | Точечные исправления ошибок OCR: применяются, только если после правки значение начинает соответствовать `pattern` |
| `serial.part_number` | нет | Как достать из серийного номера номер детали, группа 1 |
| `model.token_pattern` | нет | Форма обозначения модели этого производителя, переопределяет общую |
| `model.by_part` | нет | Соответствие номера детали модели |

## Как определяется модель по номеру детали

У Dell номер детали зашит в серийный номер: в `CN-07MT01-QDC00-74Q-0DDS-A04`
это `07MT01`. Одинаковые мониторы имеют одинаковый номер детали, поэтому,
узнав модель один раз, бот подставляет её всем такими же устройствам. Это
выручает, когда сам текст модели на фото не читается: он часто напечатан
мелко, в тени или у самого края наклейки.

Источники соответствий, в порядке приоритета:

1. Исправления пользователя — он ввёл модель вручную для устройства с таким номером детали.
2. Накопленное ботом — модель была прочитана с наклейки и карточку подтвердили.
3. Значения из `model.by_part` в этом файле.

Подставленная таким образом модель помечается в карточке как определённая по
номеру детали: она получена не с этого снимка, и пользователь должен её
подтвердить.

Команда `/parts` (для администраторов) показывает накопленные соответствия
готовым к вставке фрагментом YAML — его можно перенести в шаблон, чтобы
соответствия пережили пересоздание базы.

## Добавление производителя

Минимальный шаблон, если о формате номера ничего не известно, — только бренд и
его написания:

```yaml
brand: SAMSUNG
aliases: [SAMSUNG, SAMSUNG ELECTRONICS]
```

Такой файл уже полезен: бот будет узнавать производителя в тексте. Правила
серийного номера стоит добавлять только тогда, когда формат подтверждён на
реальных наклейках — ошибочный `pattern` приведёт к неверной канонизации
номеров.
